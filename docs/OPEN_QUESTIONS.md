# Open questions

| # | Question | URL tried | Status | What we do meanwhile |

| OQ-1 | Licence of the ENORA sites API is not stated. | https://api.enora-oah.eu/api/sites/all | Open | Use site codes, names and coordinates for the demo with attribution to ENORA and OneAquaHealth. Ask the organisers before any production reuse. |
| OQ-2 | The OAH IG CI build is not published. | https://build.fhir.org/ig/hl7-eu/oah/ (HTTP 404), .../package.tgz (404), https://packages.fhir.org/hl7.eu.fhir.oah (404, 2026-09-26) | Worked around | fhir/scripts/setup_oah.sh clones https://github.com/hl7-eu/oah at commit b907cf0869b59d82d9138b3d147fca66f333d911 into the gitignored fhir/.oah-ig/, builds it with SUSHI 3.20.1, generates snapshots with the HL7 validator 6.10.4 (`snapshot` command, because SUSHI emits differentials only), and installs the conformance resources as the local package hl7.eu.fhir.oah#0.1.0-ci-build in ~/.fhir/packages. Our SUSHI project depends on it and the validator loads it with -ig. Works offline after the first run. Replace with the official package once OAH publishes one. See fhir/README.md. |
| OQ-3 | The OAH IG repository has no LICENSE file. | https://github.com/hl7-eu/oah | Open | We reference the IG by canonical URL and do not copy its files into our repo; the validator script clones it at run time. |
